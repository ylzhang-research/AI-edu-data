Part 2 · The mechanics

The Build Bench

You have a process and you know which step needs a person. Now build the thing. Four working tools below — use them on your own process, then carry the output straight into Mini-Project 2.

What a scenario is

Exactly one trigger, then actions. The trigger is always the first module; everything after it is something that happens as a result. That is the whole structure.

Trigger→ Action→ AI step→ Action

This is input, process, output — the same diagram from Week 3, drawn in a different tool. What Make gives you for free is that it runs identically every time. What it does not give you is feedback: deciding what to learn from the output is still yours.

Tool 3 · Build the prompt

A prompt in a scenario is not a chat. In a chat you read a bad answer and try again; here nobody is watching, and the output goes straight into the next module. Fill in all four parts and watch the prompt assemble.

Four-part prompt builder

Who is the model being, in one line? Not a biography — a job.
What single thing does it do with the input?
Bound the output shape: a length, or a named set of allowed values.
What should it say when the input is empty or unusable?

The fallback is the line people forget and the one that saves them. Without it, a blank record produces a confidently invented answer — because inventing something plausible is exactly what the model does when handed nothing.

Tool 4 · Plan your five test inputs

Where AI belongs, and where it doesn't

One module. The test: if a formula could do it reliably, use the formula. AI earns its place on language and ambiguity, not on math.

Good candidates

Language and ambiguity

  • Summarize a long message into two sentences
  • Classify an item into one of a few named categories
  • Draft a first-pass reply for a human to approve
  • Extract structured fields from unstructured text
  • Flag something for a person to look at first
Poor candidates

One right answer, or no review

  • Anything with one correct answer a rule could find
  • Arithmetic, lookups, or exact matching
  • Decisions nobody reviews before they take effect
  • Anything needing context the system does not hold
  • Rewriting someone's words when the wording is the signal

When it breaks

The errors change character in Part 2. In Part 1 they were authorization errors and the message told you what was wrong. These are data errors — the message is vague, but the failing module's input panel shows exactly what arrived.

Diagnostics

What you seeWhat to do
Mapping dropdown is emptyRun the scenario once first. Make only offers fields it has actually seen.
Output is identical every runYou typed the value instead of mapping it. Click the field and select from the previous module's output.
Works on one record, fails on anotherThat is your test working. Open the failed run and read the failing module's input panel.
AI output changes shape run to runYour prompt has no format constraint. Name the allowed values or the sentence limit.
Operations disappearing fastA scheduled trigger is running whether or not there is work. Switch to polling or lengthen the interval.
A module cannot see earlier outputIt sits above the module you want, or in a different branch. Check the order.
API key rejectedIt belongs in the connection, not the prompt. Re-create the connection.
